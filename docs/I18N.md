# Thai / English translations

SYLON shows every visitor/member page in English by default. A visitor can
switch to Thai with the EN / ไทย pill in the top nav — their choice is saved
in a cookie for a year, so it's remembered on their next visit even if they
never sign in.

This doc is for **editing wording**, not for writing code. If you want to
change what a piece of text says in either language, this is the only file
you need to touch: **`lib/i18n/dictionary.ts`**.

## How to change an existing translation

1. Open `lib/i18n/dictionary.ts`.
2. Find the text you want to change. The file is organized into named
   sections (`nav`, `landing`, `tripDetail`, `manifestDetail`, `newItem`,
   `manifestEdit`, and so on) — the section names roughly match the part of
   the site they belong to. If you're not sure which section, search the
   file for a distinctive word from the English text you saw on the site.
3. Each entry looks like this:

   ```ts
   seeKanomsPlans: { en: "See Kanom's plans ↗", th: "ดูแผนของ Kanom ↗" },
   ```

   Edit the `en` string, the `th` string, or both. Keep the quotes around
   the text.
4. Save the file. If you're running the site locally, it updates
   automatically. If you're asking Claude to make the change, just say
   which word/sentence to change and what to change it to — in either
   language — and Claude will find and edit the right line here.

That's the entire workflow for wording changes — no other file needs to
change.

## How to add a brand-new piece of text

If you're adding a new label, button, or sentence somewhere on the site
(usually alongside a code change), add a new line inside the relevant
section, e.g.:

```ts
nav: dict({
  ...
  myNewLabel: { en: "My new label", th: "ป้ายใหม่ของฉัน" },
}),
```

The key name (`myNewLabel`) is just an internal identifier — pick something
short and descriptive, camelCase, not shown to users. The page code then
references it as `t(locale, "nav.myNewLabel")` (server) or
`t("nav.myNewLabel")` (client component, via `useT()`).

**Safety net:** if a key is referenced in the code but missing from the
dictionary, the page shows the literal key path (like `nav.myNewLabel`)
instead of crashing — so a typo is easy to spot while browsing, rather than
breaking the page.

## Some text changes count based on a number (pluralization)

A few strings depend on a count, like "3 trips" vs "1 trip". These use a
small helper called `tn()` instead of living as a plain dictionary entry,
because English changes the word for plural ("trip" → "trips") while Thai
doesn't — Thai just repeats the same noun after the number ("3 ทริป",
"1 ทริป"). You'll find these as `tn(locale, count, { one: "...", other:
"..." }, "ไทยคำเดียว")` calls in the component code, not in the dictionary
file. If you want to change the Thai noun used, search the codebase for the
English word next to `tn(` and edit the Thai string that's the last
argument.

## What's intentionally NOT translated (yet)

- **`/admin`** — the internal host-only management tool. It's not visitor
  or member facing, so it was left in English by design.
- **The Instagram Story image text** (`lib/story-canvas.ts`, used by the
  "Share to Story" and "Capture card" buttons). That text is drawn pixel by
  pixel onto a canvas image, not rendered as normal webpage text — adding
  Thai there means finding/adding a Thai-capable font for canvas rendering
  and re-measuring every layout for how much longer Thai text runs. It's a
  separate, bigger project from the rest of this translation pass, so the
  generated Story images stay English-only for now.
- **`components/ItemCard.tsx`** — not translated because it isn't used
  anywhere in the app right now (dead code, kept around from an earlier
  version of a card design). If it gets wired back in, it'll need the same
  `useT()` treatment the other card components already have.

## A layout detail worth knowing about

Several of the big, bold display headings on the site (the homepage hero,
personal-page hero, section titles, etc.) use very tight line spacing and
letter spacing — a stylistic choice for tracked, uppercase Latin type. Thai
script stacks vowel and tone marks above and below the letters, so that
same tightness makes Thai headlines collide into each other. To fix this
without changing the English look at all, `app/SylonDesign.module.css` has
a block near the bottom titled "Thai-script adjustments" that loosens line
spacing only when the page is in Thai (`html[lang="th"]`), only for the
handful of classes that render translated headline text. If you add a new
big display heading elsewhere on the site later and its Thai version looks
cramped, that's the block to extend — add its CSS Module class name to the
`:global(html[lang="th"]) .yourClassName` selector list there.

## How it works under the hood (for future code changes, not wording)

- `lib/i18n/dictionary.ts` — the dictionary itself, plus the `t()` and
  `tn()` lookup helpers.
- `lib/i18n/locale.ts` — reads the visitor's saved language from the
  `sylon_locale` cookie (defaults to English for first-time visitors).
- `app/actions/locale.ts` — the server action that saves the cookie when
  someone flips the switcher.
- `components/LocaleProvider.tsx` — makes the current language available
  to client components via the `useT()` hook, so most components don't
  need the language passed in as a prop.
- `components/LanguageSwitcher.tsx` — the EN / ไทย pill in the nav.

Server components call `t(locale, "section.key")` directly (after getting
`locale` from `getLocale()`); client components call `const { t } =
useT()` and then just `t("section.key")`.
